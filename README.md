# Лесная мастерская

Браузерная idle-игра для Яндекс Игр. Игрок развивает долину, производит ресурсы, продаёт их вручную, выполняет заказы и открывает новые производственные зоны.

## Запуск

Проект не использует сборщик или пакетный менеджер. Для локального запуска откройте `index.html` в браузере или поднимите любой статический HTTP-сервер в корне проекта. Для интеграции Яндекс Игр запускайте игру через платформу: в обычном браузере SDK может быть недоступен, а при `file:` SDK намеренно не инициализируется.

Основной HTML подключает модули в порядке зависимостей. При изменении JS/CSS обновляйте query-параметр версии в подключениях `index.html`, чтобы браузер не использовал старый кэш.

## Архитектура

Все модули используют общий объект `window.ForestGame`. Сборки модулей нет; скрипты подключаются напрямую из `index.html`.

| Файл | Ответственность |
| --- | --- |
| `index.html` | Разметка игрового поля, модальных экранов, панелей, доступных ресурсов и подключение скриптов. |
| `styles.css` | Визуальная система, адаптивная раскладка, анимации и состояния интерфейса. |
| `state.js` | Начальное состояние, нормализация старых сохранений, локальная загрузка/запись, экономические константы зданий. |
| `analytics.js` | Ограниченный локальный журнал игровых событий и необязательная отправка событий в настроенную Метрику. |
| `economy.js` | Производственный тик, стоимость улучшений и товаров, склад, события долины и ручная продажа. |
| `orders.js` | Каталог заказов, выбор активного заказа, расчёт прогресса/награды и отображение заказа. |
| `retention.js` | Ежедневные задания, серия входов, недельное событие и престижный экран. |
| `yandex.js` | Инициализация SDK, облачные сохранения, Gameplay API, полноэкранная и rewarded-реклама. |
| `ui.js` | Отрисовка игры и панелей, форматирование чисел, обучение, прогресс игрока и визуальные эффекты. |
| `app.js` | Связка приложения: обработчики DOM, сбор ресурсов из зон, награды, переходы, основной цикл и обработка ошибок. |

Порядок скриптов в HTML важен: `state.js` должен идти первым; `analytics.js` и `economy.js` загружаются до модулей, которые используют их API; обработчики `app.js` подключаются после разметки и всех игровых модулей.

## Игровой цикл

Основной цикл в `app.js` повторяется примерно каждые 250 мс. Он обновляет временные события, симулирует производство и вызывает облегчённую отрисовку. Панели и более тяжёлые части интерфейса обновляются не чаще раза в секунду.

Основная производственная цепочка:

```text
Лесная делянка -> брёвна -> лесопилка -> доски -> упаковочная мастерская -> ящики
```

Продажа выполняется вручную в локации рынка. Выбирается товар, затем продаётся весь его доступный запас. У каждого ресурса своя базовая цена; цена ящиков и дополнительные выплаты зависят от улучшений и активных событий.

Дополнительные цепочки открываются по уровню игрока:

| Уровень | Зона/цепочка | Действие |
| --- | --- | --- |
| 3 | Речная пристань и водяная мельница | Сбор воды; вода используется в производстве муки. |
| 4 | Ферма | Сбор зерна за воду; зерно также перерабатывается в муку. |
| 6 | Каменоломня и каменная мастерская | Сбор камня и производство кирпичей. |
| 7 | Инструментальная | Ручное создание инструмента за доски и камень. |

Вместимость склада применяется отдельно к каждому ресурсу. Улучшение склада увеличивает этот лимит. Офлайн-производство ограничено восемью часами.

## Прогресс и удержание

- Опыт и уровень игрока выдаются за заказы, сбор ресурсов и задания. Уровень открывает зоны.
- Есть пять рыночных заказов с разными ресурсами и порогами открытия. Выбирается один заказ; для ресурсных заказов товар списывается при получении награды.
- Ежедневное задание учитывает проданные ящики. Серия входов рассчитывается по локальной календарной дате устройства.
- Недельное событие детерминированно выбирается по ключу недели и даёт модификатор производства/продаж и цель с наградой.
- Короткие события долины запускаются отдельно от недельного события.
- Престиж начинает новый цикл: сбрасывает уровни зданий и складские запасы, текущий заказ, короткое событие и активный ускоритель. Дневной/недельный прогресс, их полученные награды, коллекционные предметы и серия входов сохраняются. Престижные бонусы постоянны.

## Сохранения

Локальное состояние хранится в `localStorage` под ключом `forest-workshop-save-v1`. При изменении формата сохранения обновляйте миграцию/нормализацию в `state.js` и проверяйте совместимость с уже сохранёнными данными.

В Яндекс Играх объект состояния сохраняется в облако через `player.getData`/`player.setData` по ключу `forestWorkshop`. Запись откладывается, повторяется при ошибке и принудительно отправляется при уходе со страницы. Если облачный прогресс выбран вместо локального, локальная копия перед заменой сохраняется во временную резервную запись, доступную для восстановления из профиля.

Выбор между локальным и облачным состояниями выполняется сравнением показателей прогресса в `yandex.js`; это эвристика, а не журнал операций или слияние двух сохранений.

## Яндекс Игры и реклама

`yandex.js` загружает SDK `/sdk.js` на домене Яндекс Игр и использует внешний URL SDK в локальном HTTP-окружении. После инициализации модуль:

- вызывает `LoadingAPI.ready()` и управляет `GameplayAPI.start/stop()`;
- получает профиль игрока и облачное сохранение;
- показывает полноэкранную и rewarded-рекламу;
- выдаёт награду rewarded-рекламы только из callback успешного просмотра.

Доступность рекламы зависит от окружения и ответа SDK. Кнопки бонусов отключены, пока rewarded-видео недоступно или показ уже идёт. Полноэкранная реклама вызывается после нескольких продаж с временным интервалом между показами.

## Аналитика

`analytics.js` записывает до 200 последних событий в локальный журнал `forest-workshop-analytics-v1`. Сейчас регистрируются начало сессии, завершение обучения, продажа ресурсов, выполнение заказов и получение ряда наград.

Отправка целей в Яндекс Метрику включается только если до загрузки `analytics.js` задан `window.FOREST_WORKSHOP_METRIKA_ID` и на странице доступна функция `window.ym`. В проекте не зафиксирован ID счётчика и не подключён скрипт Метрики, поэтому по умолчанию события остаются только локально.

## Интерфейс

На широком экране основные разделы доступны из боковой навигации. На мобильном экране главным навигатором служит поле с ячейками: нажатие открывает производственную локацию или собирает готовый ресурс. Заказы, профиль, цели и коллекция отображаются в выдвижных панелях. Рыночная торговля, склад и производственные здания открываются в отдельном полноэкранном слое.

Важные точки разметки:

- `#fieldGrid` — объекты мобильного поля; `data-field` определяет действие ячейки.
- `#millLocation` — переиспользуемый экран локации; выбранная локация хранится в `game.selectedMapNode`.
- `#marketTrade` — выбор продаваемого ресурса и действие продажи всего запаса.
- `#ordersPanel`, `#profilePanel`, `#achievementsPanel`, `#collectionPanel` — панели нижней/боковой навигации.
- `#gameError` — ошибки запуска, цикла игры и отсутствующих обязательных контролов.

## Изменение проекта

1. Найдите владельца поведения в таблице архитектуры и проверьте точки вызова в остальных модулях.
2. Сохраняйте совместимость сохранений через `normalizeSave()`; не переименовывайте ключи localStorage/cloud без миграции.
3. При добавлении кнопки создайте её в `index.html` и подключите обработчик в `app.js`; необязательные элементы в `ui.js` должны проверять наличие DOM-узла.
4. При изменении CSS/JS увеличьте версию ресурсов в `index.html`.
5. Для изменений экономики учитывайте офлайн-симуляцию, вместимость склада, награды заказов, недельные модификаторы и ручную продажу.

## Известные ограничения

- Архитектура модульная по файлам, но использует общий глобальный объект вместо ES-модулей и строгих интерфейсов.
- Некоторые панели и тексты обновляются непосредственно из бизнес-модулей, поэтому UI и игровая логика связаны.
- Аналитика без настроенной Метрики хранится локально; интерфейса экспорта журнала нет.
- Серия входов и начало недели используют локальные часы устройства.
- Автоматизированная сборка и пакетные команды в проекте отсутствуют.
